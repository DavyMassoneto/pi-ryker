# pi-ryker

A [pi](https://pi.dev) extension with the Global Discussion stage of the Ryker method: before any plan or code, the agent gathers the macro decisions (what and why) with you and generates a vision document for you to approve.

## Install

From a local copy of the repository:

```
pi install <path to the pi-ryker folder>
```

Version 0.1.0 is not published on npm yet (only the 0.0.x placeholder exists there). Once published: `pi install npm:pi-ryker`.

## Usage

- `/ryker <request>`: starts the discussion. Switches to an Opus model, leaves only the read tools (read, grep, find, ls) and the Ryker tools active, and the agent reads the request, the docs, the existing decisions and the code before asking.
- `/ryker`: shows the status; if the document is waiting for approval, reopens the dialog.
- `/ryker reabrir`: reopens topics that were already closed (you pick the topics and can leave a note).

If an approved discussion already exists, `/ryker <request>` asks whether it can be archived in `.ryker/arquivo/`.

## What the code guarantees

- Questions are only asked through `ryker_perguntar`: up to 4 questions per call, shown one at a time, with 2 to 5 options, the recommended one first and "Outra resposta…".
- A closed topic is not asked again; a topic you reopened only closes through a question.
- The agent closes topics without asking only with a cited source, an assumption with a reason, or a deferral with the moment to decide.
- The document is generated by the code from the state: the 11 sections, all topics, assumptions and deferred items, and the record of the questions. Assumptions go in section 9, for approval in bulk.
- A reviewer checks the document once, before you see it. A blocking finding must be resolved; the others go in an appendix.
- On approval, the previous tools and model are restored and the agent proceeds, in the same turn, to plan and execute what the vision describes, deciding the implementation choices on its own. The new Ryker has no stages after the Global Discussion yet.
- Each answer is saved immediately; Esc pauses the discussion.

## Where the state lives

`.ryker/discussao.json` (source of truth, per project), `.ryker/visao.html` (document) and `.ryker/arquivo/` (approved discussions). A snapshot also goes to the pi session. Add `.ryker` to `.gitignore` if you do not want it versioned.

## Configuration

`RYKER_ABRIR=0` prevents the document from being opened in the browser; the path is only reported.

## Known limits

- A question written as free text is not blocked: it appears in the stream and is corrected afterwards, with a forced continuation (at most 2 per run).
- `ask_user_question` (rpiv) is blocked during the stage and stays blocked after approval (while the phase is "aprovada"); during the stage the agent uses `ryker_perguntar`, afterwards it decides on its own and records the choice as an assumption.
- Interface labels exist in Portuguese and English.
